# MVP Acceptance Criteria

## Product-Level Acceptance
- MZTEK has a defined MVP boundary with clear in-scope and out-of-scope items.
- The project has a tracked work board with owners, statuses, and next tasks.
- The MVP docs are reusable for future projects, not tied to one product only.

## Functional Acceptance
- A project notebook format is defined for idea, decisions, progress, blockers, and validation.
- A task model is defined with `owner`, `status`, `dependency`, and `evidence` fields.
- A zero-trust rule set exists for rejecting unsupported completion claims.
- The next implementation step is clear without requiring rediscovery of context.

## Quality Acceptance
- Documentation is concise and readable.
- Ownership is explicit for every current MVP task.
- No file changes are made outside `E:\MZTEK\docs\project\`.
- The docs can act as the initial coordination layer for autonomous build loops.

## Exit Signal
The MVP planning layer is accepted when implementation can begin from these docs without needing a fresh product-definition conversation.
